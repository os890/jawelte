content-diff-module compares two payloads by meaning. JSON object keys may be in any order; XML attribute order doesn't matter; ignore-paths skip volatile fields (timestamps, IDs); EL placeholders interpolate runtime values into the expected document. When two payloads disagree, the failure message names the exact path and the actual-vs-expected values — no more squinting at byte-level string diffs.

1. quick-start

1.1 purpose

Asserting JSON or XML responses with assertThat(actual).isEqualTo(expected) fails the moment the server adds a whitespace or re-orders two object keys. content-diff-module parses both sides as structured documents and compares them semantically: keys, attributes, element children, with optional tolerance for ordering, missing fields, and volatile cells.

1.2 hello-world

Two JSON documents with the same keys in different order. ContentDiff.forJson(actual).expectedContent(expected).assertEquals() passes silently — the diff is structural, not byte-level.

listing content-diff-module/01 · hello-worldlistings/content-diff-module/01-hello-world/
// src/test/java/example/contentdiff/HelloDiffTest.java
class HelloDiffTest {

    @Test
    void semanticallyEqualJsonPassesSilently() {
        String actual   = "{\"name\":\"Alice\",\"age\":30}";
        String expected = "{\"age\":30,\"name\":\"Alice\"}";   // different key order

        ContentDiff.forJson(actual)
                .expectedContent(expected)
                .assertEquals();
    }
}

Two follow-up listings demonstrate the failure side and the ignoring-pattern feature:

listing content-diff-module/02 · mismatchlistings/content-diff-module/02-mismatch/
@Test
void mismatchRaisesAssertionErrorThatNamesTheOffendingField() {
    String actual   = "{\"name\":\"Alice\",\"age\":30}";
    String expected = "{\"name\":\"Alice\",\"age\":31}";

    assertThatThrownBy(() ->
            ContentDiff.forJson(actual)
                    .expectedContent(expected)
                    .assertEquals())
            .isInstanceOf(AssertionError.class)
            .hasMessageContaining("age");
}

The failure message itself names the diverging path and both sides — what the assertion above asserts via hasMessageContaining("age") is part of a richer message that looks like:

JSON diff found 1 difference(s):
  $.age: expected="31" actual="30" (expected file line 1)

The path is a JSON-Path (XPath for the XML variant) anchoring exactly which field disagreed; the parenthetical line number points back into the expected document so you can open the source dataset and edit one specific line.

listing content-diff-module/03 · ignoring-patternlistings/content-diff-module/03-ignoring-pattern/
@Test
void ignoringPatternSkipsTheNoisyField() {
    String actual   = "{\"name\":\"Alice\",\"audit\":{\"timestamp\":\"2026-05-20T10:00:00Z\"}}";
    String expected = "{\"name\":\"Alice\",\"audit\":{\"timestamp\":\"1970-01-01T00:00:00Z\"}}";

    ContentDiff.forJson(actual)
            .ignoring("$.audit.timestamp")
            .expectedContent(expected)
            .assertEquals();
}

1.3 maven setup

content-diff-module is a utility library — no CDI bootstrap, no @EnableTestBeans. The api / impl, the default EL provider (Tomcat or Expressly), Jackson for JSON, and SmallRye Config for the MP Config defaults are all you need.

2. detailed

2.1 forJson / forXml

Two factories produce typed builders bound to the supplied actual content:

  • ContentDiff.forJson(actualContent) → JsonBuilder
  • ContentDiff.forXml(actualContent) → XmlBuilder

Both builders share the same base methods: .expected("classpath/path.json") loads from the classpath, .expectedContent("...") uses an inline string (mutually exclusive), .ignoring(...) adds ignore-patterns, .withValues(Map) binds EL variables, .assertEquals() runs the comparison. JsonBuilder additionally has .unorderedArrays(...).

2.2 ignoring patterns

Each builder takes a list of path patterns to skip during the diff. The pattern dialect is dictated by the content type:

  • JSON — JSON-path style ($.audit.timestamp, $.items[*].traceId). Wildcards over array indices work.
  • XML — XPath fragments (/order/audit/timestamp, //transactionId).

Custom dialects can be plugged through JsonPatternDialect / XmlPatternDialect ports — see the SPI section.

2.3 unorderedArrays (JSON)

JSON arrays are ordered by default. JsonBuilder.unorderedArrays("$.tags", "$.items[*].labels") declares specific arrays to be compared as multisets — duplicate sensitivity preserved, element order not. Helpful for response payloads where the server emits results in an unspecified order.

2.4 EL interpolation in expected

The expected document may contain ${expression} placeholders. They're interpolated against the bindings passed to .withValues(Map) before the diff runs, which lets you parameterise the expected file:

{"createdBy": "${currentUser}", "age": 30}

Combined with .withValues(Map.of("currentUser", "alice")), the engine sees {"createdBy": "alice", "age": 30}. The EL provider is whichever Jakarta EL implementation is on the classpath — Tomcat's tomcat-embed-el is the default in jawelte's own tests; org.glassfish.expressly:expressly works as a drop-in.

2.5 MP Config defaults

Three MicroProfile Config keys carry JVM-wide defaults that are prepended to whatever the caller supplies through the builder:

KeyEffect
org.os890.jawelte.module.contentdiff.api.ContentDiff.json.ignoreComma-separated JSON-path patterns to skip on every forJson diff.
org.os890.jawelte.module.contentdiff.api.ContentDiff.xml.ignoreComma-separated XPath patterns to skip on every forXml diff.
org.os890.jawelte.module.contentdiff.api.ContentDiff.json.unordered-arraysComma-separated array paths to compare as multisets by default.

All three default to empty and are read once on first use via the active ConfigResolver, then cached for the JVM lifetime.

3. spi / port reference

content-diff-module ships four ports, all resolved via core's ServiceLoader + ServicePriorityResolver:

PortDefaultPurpose
DiffEngineJackson-backed JSON engine + JSoup/W3C-DOM XML engine in content-diff-module-implReads actual + expected content for one contentType() (e.g. application/json), returns a list of Difference. Add a custom engine for a new content type, or replace the default for the existing type to change the comparison semantics.
JsonPatternDialectJSON-path dialect in content-diff-module-implMaps an ignoring(...) pattern string to a runtime matcher. Replace to use a different JSON-path implementation (e.g. jayway/JsonPath) or a custom syntax.
XmlPatternDialectXPath dialect in content-diff-module-implThe XML equivalent of JsonPatternDialect. Custom dialects can support glob-style patterns or schema-aware matching.
ELInterpolatorJakarta EL impl in content-diff-module-implInterpolates ${...} placeholders in the expected document. Replace to use a non-EL expression language entirely.

Selection follows the standard rule: ServicePriorityResolver picks the highest-priority impl that matches the requested contentType() (or, for the dialect/interpolator ports, the highest-priority impl, period). A custom engine for an existing content type wins if it has a higher priority than the bundled default.
